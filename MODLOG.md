# Villager support — 2026-10-14

- Target: Minecraft Java 26.2, Fabric 0.19.5 / API 0.161.0, JDK 25.
- Existing worktree contains substantial pre-existing changes. Baseline snapshot: `C:/minecraftWorkflow/villager-extension-2026-10-14/before.zip`; do not reset it.
- Route: extend the existing Fabric library, share controllers using LivingEntity, preserve player API compatibility, isolate player-only item/mining operations in an unregistered action context for villagers.
- World entity remains a real vanilla Villager; no PlayerList registration, network identity or second physical body.
- Villager state belongs to entity NBT; unload/reload must pause/restore control without cloning villagers. Native AI must resume when no task/manual movement owns control.
- Validation: build/unit tests, consumer builds, isolated real Fabric-server scenarios including navigation, mining/gathering, excavation, inventory, melee/bow/shield, activity persistence, detach and player regression. Production worlds and mods are not test targets.
- Source inspection: generated exact 26.2 sources in Loom cache; extracted selected classes outside repository under the baseline directory. Existing library and regression server installations establish game/loader route; `um kb search Minecraft` and `um scan` completed.
- Status: complete. All public library controllers work with player and real villager bodies. Added creation, attach/detach, entity/kind access, inventory insertion/extraction, living-entity follow/escort, NBT persistence, actual removal hooks and dimension rebinding.
- Important findings: Fabric tracking-end is not necessarily entity removal; chunk unloading calls Entity.setRemoved directly; simulation-only tickets do not make loaded neighbor chunks entity-ticking. Use real removal hooks and radius-aware loading/simulation leases, expanded during ranged combat.
- Runtime uses actual LivingEntity dimensions, attributes, movement, shield and projectile ownership. Player-only mining/charged attack context has no PlayerList/world registration or physics tick; damage is attributed to the villager. Native AI yields only during library work/manual control. Native food slots remain independent of the working backpack.

Practicetestmod and AutonomousBots builds passed. Exact tested JAR hash and reports: `tools/regression/results/2026-10-14-villagers/summary.json`.
