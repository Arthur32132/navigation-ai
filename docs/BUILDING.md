# Сборка и проверка

Текущий кандидат: **0.2.2**, Minecraft 26.2. Упаковка этой версии по запросу
пользователя выполняется без тестов и запуска Minecraft:

```text
gradlew.bat build -x test --offline --no-daemon
gradlew.bat --stop
```

Исторические игровые команды ниже приведены как документация и не входят
в эту сборку. [Статус и изменения 0.2.2](RELEASE_0.2.2.md).

## Требования

| Инструмент | Требование |
| --- | --- |
| JDK | 25 или новее |
| Minecraft | 26.2 |
| Fabric Loader | 0.19.5 или новее |
| Fabric API | 0.161.0+26.2 |
| Gradle | используется wrapper проекта, отдельная установка не нужна |

Версии находятся в `gradle.properties`. `loom_version=1.17.21` фиксирует проверенную версию Fabric Loom; для воспроизводимой сборки используйте wrapper и зафиксированный `gradle-wrapper.properties`. `navigation_ai.accesswidener` использует namespace `official`, ожидаемый текущей версией Loom для Minecraft 26.2.

## Команды Windows

```text
gradlew.bat test
gradlew.bat clean build
gradlew.bat runServer
gradlew.bat publishToMavenLocal
```

Полная проверка с новым мирным миром, модом-потребителем, настоящим перезапуском и
природным маршрутом на 1000 блоков выполняется одной командой:

```text
python tools/regression/run-validation.py --server-template ../navigation-fixes-validation/server --profile
```

Требования к шаблону, выбор стадий и формат отчёта — в
[инструкции серверных регрессий](../tools/regression/README.md).

На Linux/macOS те же команды запускаются через `./gradlew`.

`test` запускает JUnit 5. `build` дополнительно собирает remapped JAR и sources JAR. Артефакты:

```text
build/libs/navigation-ai-0.2.2.jar
build/libs/navigation-ai-0.2.2-sources.jar
```

Публикация в локальный Maven-репозиторий использует координаты:

```text
dev.navigationai:navigation-ai:0.2.2
```

## Ручная smoke-проверка

`runServer` создаёт рабочий каталог `run`. Перед первым полноценным запуском примите EULA:

```text
run/eula.txt -> eula=true
```

Проверяйте в логах загрузку `navigation_ai`, отсутствие ошибок регистрации fake-player и корректное завершение сервера. Smoke-run не заменяет нагрузочный прогон с реальными ботами.

Проверка восстановления активной навигации на сервере: запустите `navtest spawn persist`, назначьте `navtest goto-pos persist ...`, остановите сервер во время `COMPUTING`, затем запустите его снова. После стартовой задержки runtime должен показать ту же `PositionGoal` в состоянии `RUNNING` или `SUCCESS`. Для `FollowGoal` сохранённый UUID цели проверяется после создания всех сохранённых ботов.

Для проверки журнала размещений разрешите `allowPlacing`, остановите сервер после установки первой опоры, но до завершения маршрута. После запуска отмените восстановленную задачу: неизменённая опора должна исчезнуть, а соответствующий предмет вернуться в инвентарь. Проверьте также случай, когда блок опоры был изменён вручную до отмены: откат не должен заменять чужое изменение.

## Проверка перед релизом

Проверка расширения 30.09.2026: JUnit 90/90, 146 игровых сценариев,
настоящие перезапуски сбора и шахт с сохранением бюджета, 60 смешанных заданий
и 50 одновременно идущих ботов. Результаты двух прогонов, исправление ожидания
в тесте щита, метрики и хеши артефактов приведены в
[отчёте расширения](VALIDATION_2026-09-30.md). Природный маршрут на 1000 блоков
и отдельный набор региональных маршрутов в этой проверке не запускались.

Итоговый полный прогон 27.09.2026: JUnit 72/72, 108 игровых сценариев,
настоящий перезапуск с продолжением сбора, природный маршрут 1000 блоков,
60 смешанных заданий и 50 одновременно идущих ботов. Точные результаты,
пределы производительности и хеши JAR приведены в
[отчёте](VALIDATION_2026-09-27.md).

Для повторяемых игровых проверок добычи и боя используйте
[серверную регрессию](../tools/regression/README.md). Она запускается командой
`navtest regression` в отдельном тестовом мире и проверяет 51 сценарий.
Проверка после внедрения контрактов движения 26.09.2026: JUnit 55/55,
основной серверный набор 51/51, `navreview` 15/15, `navtransitions` 9/9
без зависших задач, `navtest selftest` 22 проверки и `navtest ticket-regression`.

Регрессии ревью 26.09 запускаются командой `navfixes` в отдельном мире. Для измерения одного нагрузочного прогона используйте `navmeasure start`, затем `navtest load 50` (или `loadgen 10`) и после завершения `navmeasure stop`. Отчёт MEASURE содержит среднее, p95 и максимум полных завершённых серверных тиков отдельно от `BotRuntime.tick`; старые поля LOAD maxTickMs/avgTickMs остаются накопленными метриками runtime.

Для LOAD используйте `navmeasure load` непосредственно перед нагрузочной командой: измерение завершится автоматически после завершения задач ботов `load*`, без включения последующего простоя. Ручные `start`/`stop` измеряют весь явно заданный интервал.
Нагрузочные результаты и точные стадии проверки записаны в
[журнале проверок](../tools/regression/last-run.txt).
