# Исправления по ревью 26 сентября 2026

Исправлены десять находок глубокого ревью и шесть дополнительных проблем
исполнения, нагрузки и диагностики. Публичные сигнатуры API сохранены.
`BlockGoal.tolerance` по-прежнему измеряется до центра блока.

| Проблема | Изменение |
| --- | --- |
| Движущаяся Follow-цель постоянно отменяла поиск до начала движения | Фоновый поиск сохраняет прежний маршрут; перестроение не перезапускает незавершённый поиск, результат присоединяется из стабильной текущей позиции |
| Для занятого BlockGoal выбирался первый, иногда недоступный сосед | Один A* рассматривает все доступные соседние цели; финальный подход направлен к границе допуска |
| Плита не уменьшала доступную высоту тела | Учитывается фактическая высота поверхности и полный объём стоящего/присевшего тела, включая третий блок сверху |
| Проверка прыжка пропускала столкновение на входе в стену | Общая геометрия проверяет объём тела и промежутки между последовательными точками дуги |
| Прыжок разрешался из/в crouch-only клетку | Снимок и исполнитель запрещают такие концы прыжка и проверяют потолок обоих концов |
| Спуск не проверял верхнюю клетку колонки | Проверяется и вход на высоте исходного узла |
| maxFallDistance=0 разрешал обычный шаг вниз | Ограничение действует и на одноблочные спуски; лестница и плавание имеют отдельное исключение |
| Дешёвый длинный путь вытеснял допустимый короткий | A* хранит недоминируемые альтернативы по стоимости и числу шагов; цепочки родителей не перезаписываются |
| Callback отмены терял вложенную задачу добычи | Поколения запросов защищают добычу, сбор и бой; прерванный внешний вызов возвращает завершённую CANCELLED-задачу |
| Финальный подход обходил проверки безопасности | Проверяется объём следующего короткого отрезка, опасности, опора и поза; после спуска сначала ожидается приземление |
| Метрики описывали только последний сегмент/длину пути | В результате задачи — полное время и суммарные раскрытые узлы актуальных результатов её поисков |
| Бюджет не реагировал на нагрузку остального сервера | Используется средняя длительность полного серверного тика; чтение снимка и ресурсов имеет общий срок 2–5 мс |
| Первые боты забирали бюджет захвата | Порядок обхода стабильный со сменой первого бота каждый тик |
| Старый прыжок не проверял новый коридор полёта | Перед исполнением проверяется актуальная геометрия, опасности и живые сущности по всей дуге |
| Опоры могли строиться из магмы или без достаточного числа материалов | Ограничение количества в A*, повторная проверка материала; исключены опасные/падающие блоки и block entity |
| Сборщик сканировал до 274625 клеток за один вызов | Инкрементальный скан 512 клеток на бота/1024 на runtime за тик, очередь ближайших кандидатов и резервирование блоков между задачами |

## Регрессии

В постоянные JUnit-тесты добавлены ограничения падения/длины/материалов,
альтернативные цели, геометрия входа в стену, потолки, диагональные углы,
высота плиты и коллизии выступающих снизу блоков. Положительные проверки
сохраняют прыжки через разрывы шириной 1–3 блока и вдоль открытой двери.

`tools/regression/ReviewRegression.java` добавляет 15 игровых сценариев.
Основной набор из 51 сценария сохранён. Проверка двух последовательных
прыжков усилена: убран боковой обход, открытая панель двери расположена
параллельно второму прыжку. Успех проверяет прохождение двери.
Итоги конкретного прогона находятся в `tools/regression/last-run.txt`.

## Практические пределы

Геометрия прыжка стала общей и консервативной, но дуга остаётся приближением,
а не симуляцией ванильной физики по тикам. Полный прогноз скорости, разгона,
эффектов и состояния поверхности — следующий этап развития.

Общий срок планирования проверяется между операциями. Он не может прервать
отдельный вызов Minecraft, особенно синхронную генерацию чанка. Измерения
`NavigationMetrics` описывают время runtime; адаптация дополнительно читает
средний полный тик сервера. Нагрузочные smoke-тесты не гарантируют TPS
в произвольном мире с другими модами.

Большой радиус сбора увеличивает задержку выбора цели: полный скан радиуса
32 у одного бота требует минимум 537 тиков. Таймаут должен учитывать это
ожидание. Материалы считаются на локальном сегменте; исполнитель повторно
проверяет инвентарь, если его изменили во время работы.
